# Project persistence and transactions (WP-05)

`fcst_app.persistence.Package` reads and writes the frozen v1 manifest/model contracts. A `.fcst` file is a ZIP containing `manifest.json` and the exact declared artifacts under `model/`, `geometry/`, `sources/`, `results/`, `evidence/` and `audit/`. A flat expanded directory with that structure is readable. No executable object deserialization, imported script evaluation, vendor runtime or FreeCAD installation is involved.

The managed expanded writer uses `FORMAT.json` (`storage_layout=1`), immutable `revisions/<generation>/` directories and an atomically replaced `HEAD.json` containing the generation and manifest SHA-256. Each generation is a complete flat package. `PREVIOUS.json` retains the prior head; `SAVE.json` records prepared/committed publication. Readers select one head and never mix generations. Editing flat directories is supported through import followed by a new managed destination; the writer rejects repurposing an arbitrary nonempty directory. Unpublished generations are retained for inspection and are never automatically promoted or deleted.

ZIP saves stage a new sibling on the destination filesystem, flush and synchronize it, reopen/verify its contents, retain the current exact bytes in `<name>.previous`, write `<name>.save.json`, then replace the destination. Windows name replacement requests `MoveFileExW` write-through; SQLite uses WAL and `synchronous=FULL`. An exclusive sibling lock serializes publication. Expanded saves verify the entire staged generation before changing the head. Every save returns its committed revision/hash only after final verification and journal completion. An exception after replacement requires recovery inspection; it is never a clean-save receipt. Filesystem/device durability still depends on the platform honoring synchronization requests.

Readers enforce 2,048 members, 64 MiB per member, 256 MiB total and a maximum compression ratio of 200. Manifest/model/audit JSON uses the frozen 1 MiB/depth limits. Limits precede decompression or numerical materialization. Path rules reject absolute paths, traversal, dot/empty segments, alternate streams, backslashes, Windows reserved names, trailing dots/spaces, case aliases, file/directory collisions, links/reparse points and expanded hard links. ZIP directory records are allowed when their paths are safe. Only stored and Deflate members are supported; other codecs are rejected before their decompressors can allocate memory from untrusted dictionary parameters. Encrypted, corrupt and undeclared members fail closed. Every declared artifact must be present and match its exact size/hash; every model artifact reference must agree with the manifest; dependency IDs must close without cycles or excessive depth. Original imports/dependencies stay inert and byte-for-byte intact, regardless of suffix.

## Operational store and portable reconstruction

`ProjectStore.create(database, model)` creates a native project; `ProjectStore.create(database, package=Package.open(path))` reconstructs it without the old database. SQLite stores one project, immutable imported artifacts and their original validated manifest pins. Blob bytes and metadata are checked against those pins before mutation/export; corruption cannot become a newly trusted hash. Old operational databases with artifacts but no pins fail with `store_integrity_upgrade_required` and must be reconstructed from a checked portable package. Empty native stores remain readable. Each transaction atomically commits the canonical snapshot, revision, inverse change set, invalidations and durable actor/project/key outcome. Readers see committed snapshots. The audit/dedup retention period is the entire retained project history: no automatic expiration or pruning. At the declared 1 MiB audit capacity a mutation fails atomically instead of silently discarding retry records.

`export_package()` includes `audit/state.json` as a hashed manifest artifact. Its `storage_version=1` fields are `model_artifact_id`, `model`, `history`, `dedup`, `previews`, `derived` and `host`. The imported model artifact ID and its dependency edges survive exports. History records contain the prior validated snapshot, new revision/hash, actor/operation and inverse `restore`/`expected` entity sets. Dedup records bind actor/key, normalized request hash and committed outcome. Reconstruction checks model identity, revision/hash chains, inverse sets, outcome links, graph closure and record shapes. SQLite/WAL files and machine paths are unnecessary for portability and are never package artifacts. Package checksums provide integrity checks; they do not authenticate who authored imported history. Trusted adapters provide current actor and scopes separately.

The application API accepts typed entity upserts/deletions in one `changes.apply` operation. It validates the whole candidate model and artifact closure before any commit. Optimistic revisions prevent lost writes. An exact normalized retry returns the original outcome across restarts; changing payload, base revision, operation or plan binding with the same key fails. Distinct actors and projects have independent key spaces. Failed validation/authorization consumes no key. The frozen operation dispatcher implements `thermal.conductor.create`, `model.validate`, `model.hash` and `capabilities.get`, returning validated v1 responses. Jobs/results remain unavailable until WP-06.

Preview persists a separate random plan ID/hash, normalized payload, actor/project, base revision, exact caller scopes and expiry (at most one hour). It does not consume an apply key. Apply rechecks authority, revision, expiry, hash and candidate validity. A committed apply can still be retried after plan expiry to recover its original outcome. Undo applies a stored inverse as a new revision; an intervening edit to an affected entity rejects the inverse rather than overwriting newer work.

The derived-artifact graph records dependencies, input revision/hash and a stale flag for geometry, meshes, optics/radiation data, environments, solves, comparisons and acceptance checks. Entity references propagate changes transitively. Mapping/attachment/assumption changes invalidate all derived data conservatively. Optics and load edits invalidate their registered downstream artifacts, leaving independent branches valid. Stale live access fails; explicit historical access retains the original revision/hash. Registering a new artifact against a stale dependency fails. Producers in later work packages must register their actual dependencies; this layer does not generate meshes, radiation or solve results.

## HDF5 arrays

`fcst_app.arrays` implements [HDF5 layout v1](../spec/contracts/hdf5-v1.json) for results, conduction meshes and radiation meshes. The optional standalone `arrays` extra pins h5py 3.12.1 and NumPy 2.2.3; the Windows h5py wheel embeds HDF5 1.14.2. The exact wheel hashes are in `ci/requirements.lock`. JSON-only/native network operations use only the standard library. HDF5 operations fail explicitly when the extra is absent. This adopts an optional storage runtime, without adopting a production numerical backend or qualifying the embedded FreeCAD ABI.

The writer stores little-endian typed arrays and bounded chunks. The reader checks required role datasets, exact types, dimensions, units, finite values, UUID uniqueness, increasing time, absolute temperature, mesh connectivity and unit normals. Logical allocation budgets are checked before reading array values. External/soft/repeated hard links, virtual datasets, external raw storage, filters, object/reference datatypes and unknown datasets/attributes are rejected. Dynamic plugin loading is disabled using HDF5's documented `HDF5_PLUGIN_PRELOAD=::` setting before library import. Public upstream dependencies retain their own licenses/notices in installed wheels; binary redistribution and host packaging remain WP-19 obligations.

## Host coordination and migration

Host edits must call `mark_host_dirty()` until the host adapter can reconcile. `synchronize_host()` journals prepared revision/model/host-byte hashes, publishes host bytes, records `host_written`, then saves the package. `reconcile_host()` verifies both files and all hashes/revisions before reporting clean. Missing/changed bytes or any mismatch persist a dirty state. An imported package cannot declare the local host clean. An interrupted dual-file save remains dirty until exact reconciliation; no two-file atomicity is assumed. Actual FreeCAD edit notifications/Undo integration belong to WP-13; this work supplies and tests their service boundary with synthetic host bytes.

The [WP-04/WP-05 verification corrections](decisions/0002-wp04-wp05-verification.md) preserve imported manifest dependency edges and audit identities, bind result JSON to actual HDF5 metadata, select service snapshots under the destination lock, serialize host synchronization and reject target aliases. Actual stream reads remain bounded when files grow after a size check, and direct in-memory manifests obey the same JSON byte budget as file readers. Generated audit IDs avoid collisions with retained imported IDs. Create-only authority cannot delete or replace entities.

Migration is explicit and version-dispatched. The supported legacy `storage_version="0.9"` envelope is defined by [the synthetic legacy fixture](../tests/fixtures/persistence/legacy-0.9.json): a model-only snapshot with v0.9 version tags and otherwise v1 semantics. It is an executable migration baseline, not a claim about previously shipped FCST formats or vendor formats. Unknown versions/fields fail. Migration requires a new destination and retains the exact input as an inert original artifact. Model-only downgrade to that envelope is supported; downgrade refuses packages with arrays, source artifacts or audit journals that would be lost. Current-to-current saves retain recoverable backups. Original files are never overwritten by migration.

```text
fcst --capabilities
fcst project-inspect model.fcst
fcst project-inspect model.fcst --previous
fcst project-recover model.fcst recovered.fcst --previous
fcst project-migrate legacy.json migrated.fcst
python tools/check_persistence.py --report .local/persistence.json
python -S tools/check_security.py
python tools/verify.py --preset windows-debug
python tools/verify.py --preset windows-release
```

Both required Windows drivers execute the frozen persistence case IDs. Standard-library regressions cover transaction races, inverses, authority/expiry/retry conflicts, originals, checksum/closure/path attacks, migration, host coordination and process termination around SQLite commits. The integration driver terminates fresh processes at every write/flush/fsync/verify/backup/journal/replace/sync boundary and checks recovered current/prior revisions; it reconstructs portable retries and checks HDF5 layouts and hostile storage features. Missing, skipped, duplicated or failed required cases fail the gate.

TST-021 clears the exact generated `persistence.json` summary before upload. Public evidence contains synthetic case IDs, statuses and source hashes. Generated `.fcst`/HDF5/SQLite/host files, raw logs, source imports and machine-specific paths remain local. Publication still requires actual staged/outgoing-history/identity scans and final prose/evidence clearance.
