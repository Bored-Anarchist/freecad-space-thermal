# FreeCAD FEM reuse before host and discretization implementation

Date: 28 October 2026. Status: accepted planning direction; component adoption and qualification remain planned under WP-13/WP-16. This decision supplements the [numerical checkpoint](0001-q0-numerical.md) without changing its engine boundary or claiming an implemented FEM integration.

Planning amendment: [WP-05.5](../../plans/WP-05.5-Foundation-Reconciliation.md), displayed as WP-5.5, now owns the missing foundation inventory, API/mesher prototypes, mesh/field contract extensions, storage and representative host handoff before dependent feature acceptance. Its separate 25 planned cases and TST-022 supplement this decision. WP-13/WP-16 retain full feature implementation and the six FEM-REUSE cases below; foundation probes cannot close their production acceptance.

## Problem and decision

The specification cites FreeCAD FEM as reusable infrastructure, but the implementation has no FEM adapter, adopted FEM source or qualified FEM workflow. The existing host smoke imports `FreeCAD` and `Part` and tests geometry, document persistence and undo. WP-13 and WP-16 remain planned. The earlier plan did not require a component-level reuse assessment before implementing equivalent host and mesh features.

Evaluate reuse before building those features. Prefer supported host APIs and thin FCST adapters where they meet the canonical model, transaction, units and result contracts. Adapt compatible upstream code when an API is insufficient; implement a replacement only with a recorded technical or licensing reason and comparative evidence. Engine independence alone is not a reason to reject host-side reuse. No dependency or source license is adopted by this document.

FCST retains its host-independent model and owned thermal assembly, radiation, controls and solve lifecycle. Geometry-free networks and standalone native solving remain required. FreeCAD FEM and its external solver integrations provide useful infrastructure and comparison routes; their existence does not establish FCST spacecraft radiation, orbital loading or vendor-model compatibility.

## Required assessment and recommended dispositions

The following are recommendations to investigate, not verified APIs in the pinned host. Before the first overlapping WP-13 implementation, the FreeCAD host lead records the host candidates below and an initial mesh assessment. Before WP-16 mesh implementation, the thermal discretization lead completes the mesh-specific evidence. Both leads maintain the decisions with their implementation PRs and link them from [WP-13](https://github.com/Bored-Anarchist/freecad-space-thermal/issues/13) and [WP-16](https://github.com/Bored-Anarchist/freecad-space-thermal/issues/16).

| Candidate group | Recommended disposition | Owner and decision point | Required evidence |
|---|---|---|---|
| FEM analysis/document objects and grouping | Reuse host containers or object APIs through an adapter where compatible; keep the canonical FCST project authoritative | FreeCAD host lead; WP-13 before object implementation | Save/reopen, document ownership, canonical IDs, host dirty/reconciliation state and undo through the shared transaction API |
| FEM mesh objects, mesh I/O and Gmsh/Netgen integration | Prefer existing mesh access/generation tools to a second host meshing stack; select only qualified meshers | Thermal discretization lead with host lead; initial WP-13 assessment and final WP-16 selection | Exact mesher/build/options, connectivity, element order/orientation, length units and distinct CAD/conduction/radiation/node maps; unsupported families diagnosed |
| Material assignment, selections and thermal boundary-condition editors | Reuse suitable selection and assignment mechanisms; adapt editors to FCST quantities and operations | FreeCAD host lead with discretization lead; WP-13 before editors and WP-16 before spatial assignments | Absolute versus difference temperatures, material tensors, mapped references and integrated power; no solver-deck-specific semantics leaking into the canonical model |
| FEM result objects and postprocessing pipelines | Prefer existing mesh-field/contour infrastructure for supported fields; add FCST histories and energy views where needed | FreeCAD host lead; WP-13 before visualization | Temperature/heat-flux values, units, entity maps, sample times, invalidation and stale-result guards agree with canonical result queries |
| FEM examples, test fixtures and automation patterns | Reuse compatible synthetic cases and test patterns with attribution; independently derive numerical oracles | Host and test leads; WP-13/P0 and WP-16/Q1 | Fixture rights/provenance, unattended host execution, reproducible generated inputs and separate expected values; shared code paths cannot serve as independent physics evidence |
| CalculiX and Elmer thermal interfaces | Evaluate as optional independent conduction references; do not make them the production solver or a prerequisite for geometry-free development | Numerical and test leads; WP-16 before selecting comparison cases | Exact solver/build, equations, material laws, boundary conditions, mesh/time convergence and tolerances; actual execution mode recorded separately from `fcst_native` |

Each completed assessment must name exact upstream source paths and revision/hash, relevant public API symbols, actual FreeCAD 1.1.4/cp311 behavior, all additional runtime/build dependencies, per-file licenses/notices, compatibility with the consuming component, deployment/maintenance cost, proposed adapter boundary, measured prototype results, and a disposition of reuse API / adapt source / replace / defer. A replacement states the failed requirement or measured limitation and the smaller reuse alternatives considered. A deferred feature cannot satisfy required P0/Q1 coverage. A `main`-branch documentation link or this recommendation table is not a completed assessment.

Keep host-dependent reuse in the FreeCAD adapter. Pass immutable values, stable IDs and versioned mesh/result artifacts to the application/worker; never pass live host objects. Check actual file licenses before copying/adapting source or adding dependencies, retain required notices, and keep upstream attribution distinct from grants for newly authored FCST code. Do not infer that every FEM file or external solver shares one license.

The following case IDs are reserved planning IDs, not collected tests or completed evidence. Implement them with the affected feature, freeze quantitative criteria before running, and add the applicable IDs to the executable coverage manifest and common local/GitHub Actions drivers. Missing, skipped or unavailable required cases block the affected feature claim. An alternative implementation selected after a documented rejection must still pass the same behavior checks.

| Planned case | Required automated behavior | Owner / suites / delivery |
|---|---|---|

| FEM-REUSE-004 | Assign materials and thermal loads through reused/adapted widgets and select entities; verify SI conversion, tensor frames, integrated assigned power and canonical operation parity. | FEM-REUSE-006 | On a clean offline native installation without FreeCAD, Python, CalculiX or Elmer, run required geometry-free native acceptance. Separately, if an external conduction comparison is selected, execute its exact pinned profile with analytic/manufactured checks, energy and mesh/time refinement; retain separate backend labels and evidence. | WP-16/WP-19; SUITE-INSTALL, SUITE-PHYSICS, SUITE-GATE; Q1, with native P0 coverage unchanged |

The host supervisor owns setup, event-loop dispatch, widgets/commands, deadlines, crash recovery and evidence collection; the user performs no acceptance clicks. Mesh and field tests assert engineering data rather than just successful imports or attractive contours. Selected external comparison cases become required for that declared comparison profile; missing solvers block that profile while native development proceeds. An external pass never closes owned-engine acceptance. Analytic/manufactured, conservation and refinement checks remain independently required.

TST-008 owns assessment and host integration acceptance with WP-16 support; TST-004 and the existing spatial physics requirements own element correctness; TST-014 owns execution identity and external-reference separation. TST-021 applies to the assessment, source/license manifests, synthetic fixtures, final prose and exact bounded reports. Keep raw solver decks, generated host/project files, images and logs local until separately sanitized and cleared; preserve restricted original bytes in authorized storage.

## Sources and limits

The official [FEM workbench documentation](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/FEM_Workbench.md) describes meshing, analysis objects, external solver interfaces and postprocessing. The official [FEM introduction](https://blog.freecad.org/2025/09/16/getting-started-with-fem/) describes CalculiX and Elmer workflows and thermal loads. [Heat-flux documentation](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/FEM_ConstraintHeatflux.md) includes convection, imposed surface heat flux and surface radiation to ambient; this does not establish FCST's required coupled spacecraft radiation capability. These sources motivate candidate reuse. Qualify exact APIs against the [pinned host profile](../../ci/host-profile.json) and its matching source, as required by source-register entries S14/S22; the current generic geometry smoke supplies no FEM qualification.
