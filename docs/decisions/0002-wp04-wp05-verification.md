# WP-04/WP-05 verification corrections

Review scope: the bounded Q0 numerical checkpoint and the native package/transaction service, against implementation-plan steps 4 and 5. This supplements the original completion evidence; it does not replace or discard the sealed numerical baseline or qualify later production physics, worker or host workflows.

The review reproduced and corrected the following failures using synthetic inputs:

| Finding | Correction and executable regression |
|---|---|
| Restart assessment compared zipped prefixes, allowing missing resumed samples/components and unchecked timestamps, controls or algebraic temperatures. | `compare_restart` requires the complete predeclared sample grids on both sides of the checkpoint, finite three-component states, exact times/controls, algebraic temperatures, energy, Jacobian checks and all event times. It uses temperature and energy criteria in their declared units. `test_restart_rejects_truncation_wrong_time_controls_and_nonfinite_state` covers the rejection paths. |
| Steady assessment trusted a reported residual, including negative/nonfinite values, without independently checking returned heat balances. | `compare_steady` validates status, sample shape, finite nonnegative norm and independently reconstructed branch/algebraic balances. `test_steady_requires_finite_nonnegative_norm_and_independent_balance` includes a temperature change small enough to pass temperature tolerance but large enough to violate heat balance. |
| Internal `entity.create` accepted deletions and batches under create-only authority. | Creation now accepts exactly one insertion and no deletions; existing IDs remain rejected. `test_create_scope_cannot_delete_replace_or_batch_entities` checks atomic rejection and key retention. |
| SQLite re-export recalculated hashes from current blobs, silently accepting corrupted originals, and discarded model dependency edges and custom audit identities. | The operational store retains the imported validated manifest, verifies immutable blob bytes/metadata against its original references and preserves model path/dependencies and audit ID/dependencies. Newly generated audit IDs avoid collisions with retained imports. Corrupt or missing blobs fail before mutation/export. Old operational databases containing unpinned artifacts require reconstruction from a checked portable package; missing pins are never invented from potentially corrupted bytes. `test_original_blob_and_metadata_corruption_fail_before_rehashing` and `test_package_graph_model_path_and_audit_identity_survive_reconstruction` cover these cases. |
| Result JSON could refer to missing arrays, or arrays with different semantic hashes, node order, sample counts or quantities. | Every typed result reference must close in the manifest, and its HDF5 role/provenance/identity/shape must agree. Mesh roles and root scalar attributes are checked as well. Historical result hashes remain valid when their own metadata agrees; they need not equal the current model hash. `test_result_array_dependency_must_close_in_package` and `test_result_manifest_and_hdf5_provenance_identity_shape_must_agree` exercise the guards. |
| A delayed service save selected an old snapshot before acquiring its destination lock and could overwrite a newer publication. | Service saves select their snapshot after acquiring the destination lock. `test_delayed_save_selects_snapshot_after_destination_lock` reproduces the competing publication deterministically. |
| Overlapping host syncs could replace another operation's pending journal and report success for different host bytes; colliding paths could overwrite operational files. | Synchronization holds a project lease plus both destination locks, checks its prepared journal before advancing, and rejects aliases with package/database/sidecar paths. `test_host_sync_overlap_and_target_aliases_cannot_lose_writes` covers overlap and collision rejection. Existing crash and dirty-state tests remain required. |
| Expanded/package reads used a size check followed by an unbounded read, allowing a concurrently growing file to exceed the inspected budget. | Actual stream reads are bounded even after the initial stat; direct in-memory manifests also obey the JSON byte budget before store creation. `test_directory_reads_remain_bounded_when_size_changes_after_stat` grows a member at the read boundary. |

| A deep Windows worktree caused SUNDIALS object/library names to exceed linker path limits. | Native dependency and prototype build trees use a short, checkout-specific local application-data cache. Installed runtime copies, raw logs and sealed observations remain in each local evidence attempt. `test_native_build_cache_is_short_stable_and_checkout_scoped` checks isolation/stability; the complete native drivers execute from the previously failing deep worktree. |

No numerical tolerance, frozen Q0 case, performance budget or statistical policy is weakened. Both Windows drivers retain the numerical/reference, contract, privacy and persistence gates, with explicit coverage for the added regressions. The original Q0 prototype/source/backend evidence remains available; new attempts retain their own sealed observations and summaries.

Publication privacy (TST-021): tests and examples use synthetic inputs. Exact staged/history/identity scans and the final report/prose scans remain mandatory before upload. Public audit evidence contains case IDs, bounded verdicts and source/report hashes. Original inputs, generated project/HDF5/SQLite/host files and raw numerical/crash diagnostics remain local. The fixes do not authorize publishing any acquired engineering original or operational database.
