# Primary source register

Design baseline: **0.5**. Research date: **2026-10-26**. This register supports file interoperability, thermal-model semantics, numerical behavior, and implementation interfaces. NASA/ESA refers to files and workflows used by those teams. Proposed requirements, release targets, numerical thresholds, and architecture choices are engineering proposals. The accepted architecture uses an owned C++20 numerical engine with CMake and Python FreeCAD/API/MCP/test interfaces; Rust is an optional comparison prototype, not a dependency. Exact compiler and dependency builds are frozen at Q0. This architecture is a product decision, not a capability established by these references. Sources describe mechanisms and candidate libraries, not a tested combined FCST stack. No implementation or file compatibility has been validated by these references.

## Research limits and document control

- File compatibility is assessed per source-tool version, file family, dependency set, model feature, and operation. A NASA/ESA label alone does not identify a file format or establish interoperability.
- Some ESA/ECSS pages intermittently redirected to an ESA outage page. Research used accessible official format documentation and primary vendor documents. Before freezing adapters, retain the actual technical specifications and hashes; this register does not establish possession of a schema or permission to redistribute it.
- Official FreeCAD documentation mirrors can lag implementation. Qualify against the selected source/build/API, not an assumed version-independent behavior.
- Source/version targets are proposed tests. Vendor installations, exact deck grammars, complete project dependencies, and representative real models have not been acquired in this task.
- Public tool announcements establish advertised interface capabilities, not fidelity on a particular engineering model.
- Numerical-library and binding documentation establishes available mechanisms, not a selected, built, or tested dependency combination. C++ is the accepted implementation default; optional alternatives require the Q0 prototype evidence and an explicit decision. Compare language candidates using the same numerical backend where applicable, fixed inputs/tolerances/hardware, and correctness, memory, runtime, reproducibility, deployment, and development-effort measurements rather than unverified speed claims.
- A maintained FCST solver may use compatible numerical libraries or adopted open-source components with provenance, licenses, pinned builds, and tests. External thermal solvers remain prototype/reference backends and cannot satisfy owned-engine completion; vendor format migration and source-tool comparison/re-export are separate purposes.
- Native STEP-TAS EXPRESS schemas and proprietary vendor libraries are not included in this package. Their exact versions and permitted distribution remain acquisition items.
- The source register is deliberately primary-source based. No forum claim, AI-generated inference, or third-party compatibility marketing is treated as evidence of implemented compatibility.
