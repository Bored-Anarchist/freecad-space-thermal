# FCST contract bundle 1.0.0 (WP-03)

This is the frozen native model and interface baseline. The executable readers validate structure and engineering references, normalize SI quantities, check expression types and produce identical semantic bytes and SHA-256 hashes. They perform no solve, transaction, vendor conversion or durable job execution. Those implementations retain their own work packages and acceptance gates.

The source of truth is [generate_contracts.py](../../tools/generate_contracts.py). It generates standalone Draft 2020-12 [model](../schemas/model-v1.schema.json), [manifest](../schemas/manifest-v1.schema.json), [operation](../schemas/operation-v1.schema.json), [response](../schemas/response-v1.schema.json), [result](../schemas/result-v1.schema.json) and [worker](../schemas/worker-v1.schema.json) schemas, shared Python/C++ enumerations, the packaged Python bundle and the embedded C++ table. `--check` fails on any changed generated byte. Neither reader calls the other. A third, standard JSON Schema reader checks all positive vectors. Earlier draft schemas/examples remain archival inputs; applications use the v1 bundle.

## Identity, entities and references

All project, entity, source-map, attachment and mapping IDs are lowercase RFC 4122 UUIDs (versions 1 through 5, standard variant). Required IDs survive normalization. One snapshot cannot reuse an ID, including its project ID. Separate projects may use a declared identity map for comparison; this reader never guesses one or removes IDs from a hash. Entity IDs have checked target kinds; an ID for a frame cannot stand in for a node.

The model contains submodels, frames, geometry artifacts, CAD faces, radiation/conduction meshes, facets, conduction elements, thermal nodes, materials, optics, conductors, loads, radiation groups, environments, cases, controls and typed expressions. Results have separate immutable run records. Nodes can exist without geometry. Capacitive nodes have positive capacity; algebraic and prescribed nodes have zero capacity. Temperatures are absolute, capacity/conductance nonnegative and material density/specific heat/conductivity positive. Material temperature intervals increase. Optics fractions lie in [0,1]; specular plus transmitted fractions cannot exceed one. A conductor connects distinct existing nodes. Control thresholds increase; case times do not reverse. Case overlays target a published field with its declared dimension.

Models retain explicit assumptions and known limitations, including empty lists for native models without declared qualifications. Versioned source maps retain the source tool/version, immutable source revision hash and `(namespace, handle, entity_id)` records, with optional separate source submodel handles and node numbers. Duplicate handles in different submodels/namespaces are valid. Duplicate keys within one source map fail. Source handles never become global UUIDs. Repeated source namespaces in independent source revisions remain distinct maps. Entity diagnostics carry a validated entity UUID and, when available, its source-map UUID, with a bounded schema pointer. They omit arbitrary imported strings and source content.

Mappings are explicit many-to-many `face -> facet`, `face -> element`, `facet -> node` or `element -> node` edges with positive weights, SI areas and provenance hashes. Weights sum to one per source ID and target kind (absolute tolerance 1e-12). A face's radiation distribution and conduction distribution are separate domains. Duplicate edges and invalid target kinds fail. Thermal node identity is independent of all geometry and discretization identity.

Attachments retain source geometry revision, persistent reference, geometry signature, face UUID and attachment entity UUID. A resolved record must match all three source fields. Any face split, merge, deletion or ambiguous replacement becomes `reassignment_required`, which blocks an executable snapshot until an explicit reviewed reassignment updates the record. A signature match alone does not resolve the record. The geometry adapter must produce that change state; the contract reader cannot infer CAD topology changes from unavailable geometry.

## Quantities, frames and time

The bundle's units table specifies dimension, binary64 scale and offset. Its dimensions use exponent vectors `[mass, length, time, temperature]`. SI canonical units are K, delta_K, m, m2, s, W, J/K, W/K, W/(m*K), kg/m3, J/(kg*K), W/m2, rad, kg and 1. Absolute temperatures use `SI = value * scale + offset`; temperature differences use zero offset. Celsius and Fahrenheit absolute values cannot be used as temperature differences. The conversion executes multiplication then addition with IEEE 754 round-to-nearest binary64, without fused operations. Unit spellings are case sensitive and enumerated; unsupported units require an explicit converter before this boundary. The dimensional identity of angles remains distinct from the scalar type despite equal exponent vectors.

Scalar and tensor conductivity are expressed in W/(m*K). A tensor is symmetric positive definite and requires an orientation frame. Frame rotations are right-handed orthonormal 3x3 matrices, tolerance 1e-12, mapping local column vectors into the parent. Origins are lengths in the parent frame. Parentless frames are world frames. Translation composes as `x_parent = R * x_local + origin`; a tensor transforms as `K_parent = R * K_local * transpose(R)`. Frame/submodel cycles fail. A scalar property cannot silently replace a tensor.

Epochs are calendar timestamps `YYYY-MM-DDTHH:MM:SS` in the declared TAI or TT scale. Seconds from the epoch use SI seconds; no machine timezone is involved. UTC conversion, leap-second interpretation, ephemeris and calendar validation beyond the lexical contract belong to the environment adapter. TT is TAI + 32.184 seconds. Adapters must provide a declared conversion artifact before an unsupported time scale can enter a model. Property ranges and case times are inputs; solver-dependent interpolation or operating-range excursions require explicit diagnostics at execution.

## Expressions

Expressions are inert JSON ASTs with literals, expression UUID symbols, add/subtract/multiply/divide, min/max, negate/abs/sqrt, exp/log, sin/cos and tables. Child evaluation order is left to right, depth first; referenced expressions are memoized per evaluation context. No source-language text, function lookup, import, host call or executable blob is evaluated. Duplicate/undefined symbols and cycles fail before solving. AST nesting and reference chains are bounded to 64.

Dependency limits measure the longest path in the complete graph, counting a leaf as one and each referenced entity/artifact as another, with at most 64 records on a path. Validation resolves targets, detects cycles, computes graph heights and then checks expression types in deterministic children-first UUID order. Serialization order and previously cached children cannot shorten a path. Manifest dependency graphs use the same rule. JSON nesting is counted only when entering child values; schema references and union alternatives use a separate per-value traversal budget, so a valid expression is not rejected merely because its schema has several reference layers.

Add/subtract/min/max require equal dimensions, with these absolute-temperature rules: absolute minus absolute produces a difference; absolute plus difference (either order) and absolute minus difference produce absolute temperature. Two absolutes cannot be added; absolute temperatures cannot be multiplied, divided, negated or passed to transcendental functions. Multiplication/division add/subtract exponent vectors and must produce a published dimension. `sqrt` halves them; exp/log require a scalar; sin/cos accept scalar radians or angle and return scalar. Domain errors (division by zero, negative square roots, nonpositive logarithms, overflow) fail at evaluation rather than producing NaN. Expressions declare their result dimension, which must match inference. A load expression must yield power. Source-specific language semantics must be translated/reviewed by WP-07.

Tables require equal x/y lengths, one dimension per axis and strictly increasing normalized x. Interpolation is explicitly `linear` or previous-value interval selection `previous`: for `x[i] <= x < x[i+1]`, use `y[i]`; at the final knot use the final value. Extrapolation is `error` or endpoint `clamp`. Declared discontinuity indexes identify the right side of jumps and require `previous`, preventing linear interpolation across them. Runtime domain checks and event sampling remain WP-04/WP-11 obligations; WP-03 validates the type and table contract without a solve.

## Versions and hashes

All new contracts carry `contract_version: 1.0.0`; model/result records and capabilities additionally require `minimum_reader: 1.0.0`. Unsupported versions or minimum readers fail before any operation can mutate state. Unknown fields fail closed. There is no implicit migration from archival drafts and no executable migration payload. A future release must publish deterministic migrations, preserve originals and declare its exact read-compatibility matrix and minimum reader. Unsupported downgrades fail; this bundle reads and writes only 1.0.0. Major versions may change meaning; minor additions require negotiated capabilities and explicit reader support. No reader assumes that an unknown minor version is safe.

JSON inputs are UTF-8, at most 1 MiB and depth 64, with unique object keys, finite binary64 numbers and no trailing data. Invalid UTF-8, unpaired surrogates, nonfinite literals, overflow and lexical nonzero underflow fail. Integers are bounded to 2^53-1 where used as counts/revisions. All schema numbers are represented as binary64; invalid property ranges fail independently of schema checks. The native reader uses strict floating-point compiler flags.

Unicode validity applies to decoded object keys as well as values, including nested objects. Invalid surrogate keys yield `invalid_json` in both readers; valid supplementary characters remain supported.

Semantic normalization converts quantities to SI, removes model `audit`, `gui` and project `revision`, sorts entity/source-map/mapping/attachment arrays by UUID, source entries by namespace/handle/entity UUID, and set-valued facet/exclusion/load/control ID arrays lexically. Other arrays retain order, including AST children, tensor axes, table knots, overlays and result array indexes. Labels, required IDs, geometry revisions, source provenance and artifact references remain semantic inputs. Revisions cannot make unchanged engineering appear changed, but stale-result application must independently compare the project revision in WP-05/WP-06.

Canonical bytes use unambiguous prefix coding: null `n`, booleans `t`/`f`, numbers `d` followed by 16 lowercase hex digits of their big-endian binary64 representation, strings `s<UTF-8-byte-length>:<bytes>`, arrays `a<count>:<children>`, objects `o<count>:<key><value>...` with keys sorted by Unicode scalar order. Signed zero becomes positive zero. Object keys are strings. Strings preserve Unicode code points without NFC normalization. UTF-8 byte lexical order gives the same key order. There are no whitespace or locale-dependent number strings in canonical bytes.

The semantic hash is SHA-256 over ASCII `FCST-semantic-v1`, a zero byte, then canonical bytes. Artifact hashes cover exact file bytes including whitespace and byte order. Build hashes cover a separately serialized build/dependency manifest; they are never reused as model hashes. The fixture manifest freezes expected positive hashes. Changing a required ID, ordered input or referenced artifact hash changes the semantic hash. Independently generated models require an explicit external identity mapping to compare equivalent engineering.

## Operations and results

Every [operation](../schemas/operation-v1.schema.json) includes a project UUID, expected revision, idempotency UUID and closed arguments. The bundle defines arguments and success responses for `model.validate`, `model.hash`, `capabilities.get`, `thermal.conductor.create`, `job.submit`, `job.cancel` and paged `result.query`. Unknown operations fail with `unsupported_operation`. Failures use a typed diagnostic; optional source/entity IDs refer to validated identities. Capability negotiation advertises supported operation names and reader versions; a published argument schema does not grant authorization or claim runtime implementation.

This package implements validation and hashing only. Transaction dispatch, durable deduplication, preview/apply authority, authorization and mutation belong to WP-05/WP-14; real jobs belong to WP-06. Unsupported execution continues to return `not_implemented`. No validation result means a solve has succeeded. A conductor creation must check live node existence/project/revision and authorization at the application boundary before commit; schema validation alone cannot establish those facts.

Result records separate engine mode (`fcst_native`, `prototype_external`, `reference_external`, `fallback_external`), adapter identity, build hash, model semantic hash, revision, case ID, outcome, diagnostics, node order, time count, quantity names and exact data artifact reference. Source adapters must normalize units/sign conventions and preserve interpolation provenance before this native result contract. Only actual owned-engine execution may populate qualifying native evidence. Results are immutable; a changed live model marks application stale without destroying historically valid results.

## Storage and worker protocol

The v1 package manifest binds the project/revision and canonical model artifact UUID to an inventory of typed artifacts and explicit dependency UUIDs. Readers reject duplicate UUIDs, case-insensitive path aliases, missing dependency targets and cycles. Each artifact reference records its relative path, exact SHA-256 and byte length. The package reader must verify those bytes and the model/project revision pairing before commit. The manifest declares storage; ZIP/directory safety, durable writes and migration/recovery implementation remain WP-05.

See [the HDF5 layout](hdf5-v1.json) for dataset paths, shapes, dtypes, units and root attributes. Result arrays use explicit `/index/node_uuid[N,16]` RFC 4122 network-order UUID bytes, equal to the JSON node array order. Mesh arrays similarly map each row using `/index/entity_uuid[E,16]`. Array indexes are zero based and never source node numbers. All numeric arrays are little-endian, contiguous row-major logical order, finite, with no implicit scale/offset. Temperature is K, net applied power is positive into the node, residual is assembled imbalance in W (incoming minus outgoing). Time is strictly increasing SI seconds relative to the case epoch and must not cross an event without an explicitly sampled event policy. T is the JSON `time_count`; N is its node-ID count. All quantities listed in the JSON run record have required datasets `[T,N]`. Unknown datasets, links, external storage, virtual datasets and executable/user-defined filters fail closed at the future persistence reader.

UUID indexes are unique and every indexed entity must exist in the JSON snapshot. Mesh vertices are `[V,3]` in the mesh frame; connectivity uses CSR offsets `[E+1]` starting at zero, increasing to L, and vertex indexes `[L]` strictly below V. Radiation rows are triangular facets with three distinct indexes and normalized outward normals `[E,3]`; front/back activation is the facet side. Conduction rows have the topology declared by their element record. CAD boundary representation bytes stay in geometry artifacts; they do not become thermal nodes. JSON remains authoritative for mapping edges, weights, frame rotations and conductivity tensors; no second HDF5 copy can override them.

HDF5 result chunks are `[min(T,256), min(N,1024)]`; time chunks are `[min(T,256)]`, index chunks `[min(N,1024),16]`. Mesh chunks are at most 1024 rows with complete trailing axes; connectivity chunks are at most 8192 entries. Compression is none in v1. Datasets carry scalar UTF-8 `unit` attributes and the file carries the declared root attributes. Exact HDF5 bytes are hashed as artifacts; repacking may preserve semantics while changing the artifact hash. HDF5 writer/reader, package transactions and recovery are WP-05; the WP-03 layout is a storage contract, without adopting the packaging-probe HDF5 library as a production dependency.

Worker control messages are a four-byte unsigned little-endian UTF-8 payload length (1 through 65536), followed by exactly that many JSON bytes. EOF mid-header/body, zero/oversized length, trailing bytes in a single-frame call and malformed payloads fail. Streaming transport reads successive bounded frames. Large arrays remain verified local artifacts. Paths are package-relative ASCII with no empty/dot/traversal components, trailing dots/spaces or Windows reserved device names; receivers resolve below their trusted artifact root, reject links/reparse points and verify byte length/SHA-256 before use. A peer never supplies an arbitrary host path.

The message union covers handshake/capabilities, submit with snapshot/hash/case references, progress, diagnostics, cancel, one terminal outcome and checkpoints. Per-job sequences begin at zero and increase by one in the serialized transcript. A handshake precedes submit; running jobs accept progress/diagnostics/checkpoints/cancel/terminal; cancel requests are cooperative and do not themselves mean cancellation completed. A terminal may still succeed after a cancel race. Only a success terminal includes a result reference; failed/cancelled terminals do not claim a result. No message follows terminal. Checkpoints bind case, snapshot/build hashes, time, sequence and exact state artifact. Restart compatibility must check all of these; a checkpoint cannot silently change model/build. The reference transcript validator checks ordering, job scope and snapshot binding; WP-06 supplies process isolation, durable delivery, cancellation timeout and restart implementation.

Checkpoint `time` is a time-dimension quantity normalized to SI seconds. Both direct message and framed-message readers reject power, absolute temperature and other non-time quantities with `dimension`; for example, three minutes normalize to 180 seconds.

## Executable acceptance and inventory reconciliation

`python tools/verify.py --preset windows-debug` (and `windows-release`) checks generated-byte drift, Python regressions, the standard schema reader, native build/install/engine-only tests and independent C++/Python conformance. `python tools/check_contracts.py --worker <installed-worker>` runs all frozen positive/negative vectors and native framing cases. Expected hashes are fixed before publication. A missing, duplicated, skipped or mismatched case fails the common coverage gate. Raw output stays local; bounded evidence is privacy-scanned before upload under TST-021.

| Acquired WP-01 feature | v1 representation and acceptance | Later obligation |
|---|---|---|
| F-IDENTITY | Source namespace/handle maps; duplicate handles across submodels pass, collisions fail | WP-07/08/09 preserve adapter round trips |
| F-UNITS | SI/absolute/difference unit table; Celsius/Fahrenheit and imperial normalization, range/type failures | Vendor conversion tolerance qualification |
| F-EXPRESSIONS | Closed typed AST, tables, symbol/cycle/type checks; imported source remains inert | WP-07 source-language translation and WP-11 runtime domains/events |
| F-GEOMETRY | Distinct faces/facets/elements/nodes; weighted mappings, orientation and explicit reassignment | WP-13/16 geometry change/discretization behavior |
| F-MATERIALS/F-RESULTS | Typed tensor/range and immutable result/array contracts | WP-16 property runtime and WP-08/09 source result mapping |
| Other acquired and missing advanced features | Profile dispositions and owners remain in inventory | No new compatibility, physics or complete-Q0 claim |

The acquired inventory and all 12 unqualified profiles have been reconciled with these contracts. No original engineering bytes are changed or uploaded. Open exact-version, rights, vendor-runtime, source-result, EXPRESS and advanced-feature gaps retain their owners in [inventory/gaps.json](../../inventory/gaps.json). WP-03 closure freezes this native contract baseline; Q0 still requires WP-04's numerical/backend decision. Advanced fluid, spectral optics, ephemerides and vendor-specific lossless syntax require explicitly versioned extensions at their owning work packages and cannot be represented as silently accepted unknown fields.
